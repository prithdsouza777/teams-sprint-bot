# AI Scrum Bot - Project Update

**Date:** 2026-02-10
**Type:** Project Context & Architecture
**Status:** Active Development

## 🤖 Project Overview
An AI-powered Microsoft Teams bot that automates daily standup meetings. It uses **Gemini 1.5 Flash** for intelligence, **FastAPI** for the backend, and **AWS Polly** for voice features (optional).

### 🛠 Tech Stack
- **Framework:** FastAPI + Uvicorn
- **Bot SDK:** `botbuilder-python`
- **AI Model:** Gemini 1.5 Flash
- **Database:** MongoDB (Motor) for tasks/users, Firestore for session state
- **TTS:** AWS Polly
- **Deployment:** GCP Cloud Run / Azure

## 🧠 Agent Architecture

The core logic resides in `app/agent/graph.py` and is driven by the `AgentState`.

### State Management (`app/agent/state.py`)
The `AgentState` object persists the context of the standup:
- **Participants:** List of users in the standup.
- **Current Context:** `current_speaker`, `current_tasks`, `participant_index`.
- **Progress:** `covered_task_ids` (tracks which tasks have been discussed).
- **History:** `conversation_history` (used for context-aware follow-ups).
- **Output:** `responses` (list of `StandupResponse` objects), `final_summary`.

### Workflow Logic (`run_standup_agent`)
The agent follows a cyclic process for each participant:

1.  **Identify Speaker** (`identify_speaker`)
    -   Selects the next user from the participants list.
    -   If no more participants, marks `is_complete = True`.

2.  **Fetch Tasks** (`fetch_tasks`)
    -   Retrieves `TODO`, `IN_PROGRESS`, etc., tasks from MongoDB for the current speaker.

3.  **Ask Question** (`ask_question`)
    -   **Initial Question:** Asks about general progress and specific active tasks.
    -   **Follow-up logic:** If the user answers but misses specific tasks, the agent generates a targeted follow-up question ("What about task X?").
    -   *Key Feature:* Uses `covered_task_ids` to ensure all tasks are addressed before moving on.

4.  **Process Answer** (`process_answer`)
    -   **Analysis:** Uses Gemini (`analyze_standup_response`) to extract task updates and blockers.
    -   **Updates DB:** Automatically updates task status in MongoDB (e.g., "I finished the login page" -> Sets status to `DONE`).
    -   **Completion Check:** If all tasks are covered, moves to the next participant. If not, loops back to `ask_question`.

5.  **Summarize** (`summarize_meeting`)
    -   Once all participants are done, generates a meeting summary with key accomplishments, focus areas, and blockers.

## 📝 Prompts & Personas (`app/agent/prompts.py`)

### Scrum Master Persona
> "You are an experienced Scrum Master conducting a daily standup meeting... Ask each team member about their progress, Identify blockers... Keep the meeting focused."

### Key Prompts
-   **`SCRUM_MASTER_PROMPT`**: Used for generating the initial question based on the user's task list.
-   **`SUMMARY_PROMPT`**: strict format for the final summary (Accomplishments, Focus, Blockers, Action Items).
-   **`TASK_ASSIGNMENT_PROMPT`**: Zero-shot JSON extraction for assigning tasks ("Assign task X to Y").
